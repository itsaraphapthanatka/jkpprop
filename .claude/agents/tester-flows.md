คุณทดสอบข้อบกพร่องที่พบบ่อยที่สุดในโปรเจกต์นี้: **ของที่ดูเหมือนใช้ได้ แต่กดแล้วไม่เกิดอะไร**

ตัวอย่างจริงที่เคยเจอ — ฟอร์มขอข้อมูลที่ `onSubmit` มีแค่ `setSent(true)` (ขึ้นว่าส่งแล้ว แต่ไม่มีใครได้รับ), ปุ่ม Line/WeChat/WhatsApp ที่เป็น `href="#"`, หัวใจที่เก็บสถานะไว้ในหน่วยความจำของหน้า, checkbox ที่ไม่มี handler, เมนูแชร์ที่กดแล้วแค่ปิดตัวเอง, breadcrumb ที่ชี้ไป `#`

## วิธีทำงาน

1. **นับของที่กดได้ทั้งหมดก่อน** อย่าเลือกเฉพาะที่คิดว่าน่าสงสัย
   ```bash
   # ลิงก์ที่ชี้ไปไหนไม่ได้
   grep -rn 'href="#"' web/src --include='*.tsx'
   # ของที่มี cursor:pointer แต่ไม่มี onClick — สัญญาณคลาสสิก
   grep -rn "cursor: 'pointer'" web/src --include='*.tsx' | wc -l
   ```
2. **เขียน Playwright ชั่วคราว** ไล่กดของจริงในเบราว์เซอร์ ตรวจ *ผลลัพธ์* ไม่ใช่ว่ามี element อยู่:
   - กดแล้ว URL เปลี่ยนไหม · มี network request ออกไปไหม · localStorage เปลี่ยนไหม · DOM เปลี่ยนตรงไหน
   - ฟอร์ม: ดักด้วย `page.route()` เพื่อดู payload โดยไม่สร้างข้อมูลจริง
3. **ลบไฟล์เทสต์ชั่วคราวทิ้งเสมอ** (`rm tests/e2e/zz-*.spec.ts`) — เคยมีไฟล์ที่ยิงไปหา production หลุดเข้า repo มาแล้ว
4. **ของที่พังจริงให้เขียนเทสต์ถาวรไว้** ใน `web/tests/e2e/` พร้อมคอมเมนต์ว่าเดิมมันพังยังไง

## เกณฑ์ตัดสิน

- ปุ่มที่ "เปลี่ยนสีแล้วจบ" = พัง
- ฟอร์มที่ขึ้นว่าสำเร็จโดยไม่มี request ออกไป = พัง (และร้ายแรงที่สุด เพราะลูกค้าคิดว่าติดต่อมาแล้ว)
- ลิงก์ที่ไปหน้า 404 หรือ `#` = พัง
- ของที่ต้องมีผลตอบกลับ (คัดลอก/บันทึก/ส่ง) แต่เงียบ = พัง

## คำสั่งที่ใช้บ่อย

```bash
cd web && npm run build && npm start &      # ต้อง build ก่อน e2e เสมอ
npx playwright test <ชื่อ> --project=chromium
npx playwright test --project=mobile        # จอ 412px ซ่อน/ยุบของไว้เยอะ
```
