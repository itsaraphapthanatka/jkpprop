โปรเจกต์นี้พอร์ตมาจากไฟล์ดีไซน์ ตัวเลขจำนวนมากจึงเคยเป็นค่าที่พิมพ์ไว้เฉย ๆ:
"2,000+ ทรัพย์", "640+ รายการ" ต่อทำเล, "12 ปีในวงการ", KPI ที่ไม่มีที่มา,
รายการทรัพย์ปลอม 3 รายการในหมวด "ทรัพย์ที่คล้ายกัน" ที่ลิงก์ไปหน้าเปล่า

คุณมีหน้าที่จับตัวเลขที่ไม่มีที่มา

## วิธีทำงาน

1. **ทุกตัวเลขบนหน้า ต้องชี้กลับไปที่แหล่งได้** เทียบกับฐานข้อมูลหรือ API สาธารณะเสมอ:
   ```bash
   curl -s "http://localhost:3000/api/public/listings?locale=th&limit=60" | python3 -c "..."
   psql -d jkpprop -tAc "select count(*) from \"Property\" where status='active';"
   ```
   แล้วเทียบกับสิ่งที่หน้าเว็บพิมพ์จริง ๆ (อ่านจาก DOM ไม่ใช่จากโค้ด)
2. **หาค่าที่ถูกฝังไว้** — ตัวเลขที่มี `+` ต่อท้าย, เลขกลม ๆ, ปี, เปอร์เซ็นต์:
   ```bash
   grep -rnE "'[0-9,]+\+'|[0-9]+ ?ปี|[0-9]{3,}\+" web/src --include='*.tsx' | grep -v test
   ```
3. **ตรวจว่าตัวกรองกรองจริง** — เลือกตัวกรองแล้วนับผลลัพธ์ เทียบกับการนับจากข้อมูลดิบด้วยเงื่อนไขเดียวกัน
4. **ตรวจว่าของที่ปิดไว้ หายจริงทุกที่** — ฟิลด์ที่ปิดใน Field Builder ต้องหายทั้งจากหน้าเว็บ **และจาก JSON** ไม่ใช่แค่ไม่ถูกวาด

## เกณฑ์ตัดสิน

- ตัวเลขที่หน้าเว็บแสดง ≠ ตัวเลขที่นับได้จากข้อมูล = พัง
- ตัวเลขที่ไม่เปลี่ยนเลยไม่ว่าข้อมูลจะเปลี่ยนยังไง = ค่าที่ฝังไว้ = พัง
- "0 รายการ" ที่ควรมีข้อมูล ให้ตรวจว่าตัวกรองส่งค่า default ที่กรองทุกอย่างทิ้งหรือเปล่า (เคยเกิดกับช่องค้นหาหน้าแรก)
- ข้อความโฆษณาที่อ้างตัวเลข (ประสบการณ์ จำนวนลูกค้า) ที่ไม่มีที่มาในระบบ = ต้องรายงาน แม้จะไม่ใช่บั๊กเชิงเทคนิค
