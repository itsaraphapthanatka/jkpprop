# นำเข้าทรัพย์และประกาศจากไฟล์ CSV

สำหรับย้ายข้อมูลทรัพย์เข้าระบบทีละหลายรายการ แทนการกรอกทีละรายการใน `/admin/properties`

> **เอกสารนี้สำหรับคนที่รันคำสั่งได้** — ทีมงานที่กรอกไฟล์อย่างเดียวให้ใช้
> [`docs/import-guide.html`](docs/import-guide.html) แทน (เปิดในเบราว์เซอร์ได้เลย)
> อธิบายการกรอกแต่ละชนิดข้อมูล ค่าที่ต้องพิมพ์ให้ตรง และรายการเช็กก่อนส่งไฟล์
> โดยไม่มีคำสั่งเทอร์มินัลให้สับสน

---

## 1. เอาเทมเพลตมาก่อน

```bash
cd web
npm run import:template              # ได้ครบทุกประเภท
npm run import:template -- factory   # เอาเฉพาะโรงงาน
```

ได้ไฟล์ในโฟลเดอร์ `import-templates/` ประเภทละ 2 ไฟล์

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `factory.csv` | ไฟล์ที่กรอกจริง — บรรทัดแรกคือชื่อคอลัมน์ |
| `factory-อธิบาย.csv` | อธิบายแต่ละคอลัมน์ ชนิดข้อมูล และค่าที่เลือกได้ |

คอลัมน์ถูกสร้างจาก `lib/propertySchema` ซึ่งเป็นตัวเดียวกับที่ฟอร์มใน admin ใช้
เพิ่มฟิลด์ใน Field Builder แล้วสั่ง `npm run import:template` ใหม่ คอลัมน์จะตามมาเอง

## 2. กรอกข้อมูล

เปิดด้วย Excel / Google Sheets ได้เลย (ไฟล์เป็น UTF-8 พร้อม BOM ภาษาไทยไม่เพี้ยน)

**ลบแถวตัวอย่างทิ้งก่อน** แล้วกรอกทีละแถว หนึ่งแถว = หนึ่งทรัพย์

คอลัมน์ที่ทุกไฟล์มีเหมือนกัน:

| คอลัมน์ | ความหมาย |
|---|---|
| `public_code` | **เว้นว่าง = สร้างใหม่** ระบบออกรหัสให้ · ใส่รหัสเดิม = แก้ไขทรัพย์นั้น |
| `title` | ชื่อทรัพย์ — จำเป็น |
| `status` | `draft` \| `active` \| `hidden` — เว้นว่าง = `draft` |
| `listing_status` | `draft` \| `published` \| `hidden` \| `unavailable` \| `archived` — เว้นว่าง = ไม่สร้างประกาศ |

รูปแบบข้อมูลในช่องอื่น:

- **ตัวเลข / ราคา** — ใส่แต่ตัวเลข `350000` (มี `,` หรือ `฿` ก็ได้ ระบบตัดให้)
- **เลือกหลายค่า / รูป** — คั่นด้วย `|` เช่น `เครนเหนือศีรษะ|บนถนนสายหลัก`
- **ใช่/ไม่ใช่** — `true` / `false` หรือ `ใช่` / `ไม่ใช่`
- **วันที่** — `YYYY-MM-DD`
- **ตัวเลือก** — ต้องตรงกับค่าในไฟล์อธิบายเป๊ะ ๆ (เช่น `3 Phase 50/150A` ไม่ใช่ `3 เฟส`)

> รูปภาพต้องอัปโหลดที่ `/admin/media` ก่อน แล้วคัดลอกลิงก์มาใส่ช่อง `photos`
> CSV แนบไฟล์รูปมาด้วยไม่ได้

## 3. ตรวจก่อน แล้วค่อยเขียน

```bash
npm run import:properties -- import-templates/factory.csv            # ตรวจอย่างเดียว
npm run import:properties -- import-templates/factory.csv --commit   # เขียนจริง
```

ระบบเดาประเภททรัพย์จากชื่อไฟล์ ถ้าเปลี่ยนชื่อไฟล์แล้วให้ระบุเอง:

```bash
npm run import:properties -- ทรัพย์เดือนสิงหา.csv --type warehouse --commit
```

**ค่าเริ่มต้นคือตรวจอย่างเดียว ไม่เขียนอะไร** ต้องใส่ `--commit` ถึงจะเขียน

รายงานจะบอกบรรทัดที่มีปัญหาแบบเจาะจง:

```
❌ พบปัญหา 3 จุด — ไม่มีการเขียนข้อมูลใด ๆ

  บรรทัด    3  title              ต้องมีชื่อทรัพย์
  บรรทัด    4  deal_type          "ให้เช่าาา" ไม่อยู่ในรายการ — เลือกได้: ขาย | ปล่อยเช่า | ขายและปล่อยเช่า
  บรรทัด    4  usable_area        "abc" ไม่ใช่ตัวเลข
```

**ถ้ามีแถวไหนผิด จะไม่เขียนสักแถว** พิมพ์ผิดบรรทัด 60 จะได้ไม่เหลือทรัพย์ค้างครึ่ง ๆ กลาง ๆ 59 รายการ

## เรื่องที่ต้องรู้ก่อนใช้กับ production

**รหัสทรัพย์เปลี่ยนไม่ได้** — `public_code` ออกครั้งเดียวแล้วแก้ไม่ได้ตลอดไป (FR-ADM-08)
นำเข้าผิดแล้วลบทิ้ง เลขที่ถูกใช้ไปแล้วก็ไม่ย้อนกลับ **ตรวจให้ผ่านก่อนเสมอ**

**รหัสออกตามจังหวัด** — กรุงเทพฯ ได้ `JKP0001` จังหวัดอื่นได้ `JKP-CBI0001`
ถ้าไม่กรอกช่อง `province` จะได้รูปแบบกรุงเทพฯ ไปด้วย

**สำรองก่อนนำเข้าชุดใหญ่**

```bash
ssh root@<vps> 'cd /srv/jkpprop && ./scripts/backup-db.sh'
```

**นำเข้าเข้าฐานข้อมูลไหน** ดูที่ `DATABASE_URL` — จะรันใส่ production ต้องต่อผ่าน SSH tunnel
(ดู [DEPLOY_NGINX.md](../DEPLOY_NGINX.md)) หรือรันบนเครื่อง VPS เอง

**ทุกแถวถูกบันทึกใน audit log** ด้วย action `property.import_create` / `property.import_update`
ตรวจย้อนหลังได้ที่ `/admin/audit`

## ข้อจำกัดที่ยังมี

- ยังไม่มีหน้าอัปโหลดไฟล์ใน admin — ต้องรันคำสั่งจากเครื่องที่ต่อฐานข้อมูลได้
- หนึ่งไฟล์ = หนึ่งประเภททรัพย์ (คอลัมน์ของแต่ละประเภทไม่เหมือนกัน)
- ยังไม่รองรับการลบทรัพย์ผ่านไฟล์ — ตั้งใจ เพราะลบพลาดกู้ยากกว่าสร้างพลาด
